## 1. The Practical Challenge

In high-concurrency relational database systems (such as **PostgreSQL**, **MySQL InnoDB**, and **Oracle Database**), transactions constantly acquire and hold exclusive row-level locks. When two or more transactions request locks held by each other in circular sequence, execution freezes indefinitely.

### Engineering Requirements

Your task in `backend-lab` is to implement an enterprise-grade **Transactional Lock Manager and Deadlock Resolution Engine** matching PostgreSQL's internal lock manager architecture:

1. **Wait-For Graph (WFG) Topology:** Construct a thread-safe directed graph $G = (V, E)$ dynamically tracking lock holders and blocked waiters.
2. **$\mathcal{O}(V + E)$ Cycle Detection:** Implement **Robert Tarjan's Strongly Connected Components (SCC)** algorithm to identify circular dependencies immediately upon lock contention.
3. **Cost-Weighted Victim Selection:** When a cycle is detected, formulate a multi-variable rollback cost metric and abort the transaction that minimizes discarded computational work:
   $$T^* = \arg\min_{T \in C} \text{Cost}(T)$$
4. **Clean Abort & Cascade Release:** Signal the victim with a `DeadlockException` (PostgreSQL error `40P01`), release all its held locks, update the WFG, and unblock waiting threads without race conditions.
5. **Java 21 Concurrency:** Verify the suite under concurrent Virtual Threads.

## 2. Formal Mathematical Proofs

Before inspecting the Java implementation, we establish the formal discrete proofs guaranteeing correctness and performance.

### 2.1 Theorem 1: Cycle-Deadlock Equivalence

<div class="math-theorem">
  <div class="theorem-header">Theorem 1 (Cycle-Deadlock Equivalence)</div>
  <p>
    Let $G = (V, E)$ be a Wait-For Graph where vertices $V$ represent active transactions and directed edges $(u \to v) \in E$ represent transaction $u$ blocked waiting for an exclusive lock currently held by transaction $v$.
  </p>
  <p>
    A set of transactions $S \subseteq V$ is in a circular deadlock state <strong>if and only if</strong> the induced subgraph $G[S]$ contains a directed cycle.
  </p>
</div>

#### Proof:

**Part 1: $(\Longleftarrow)$ Directed Cycle $\implies$ Deadlock State**

1. Assume $G[S]$ contains a directed cycle $C$ of length $k \ge 2$:
   $$C = (v_0 \longrightarrow v_1 \longrightarrow v_2 \longrightarrow \ldots \longrightarrow v_{k-1} \longrightarrow v_0)$$
2. By definition of the Wait-For Graph:
   * Edge $(v_0 \to v_1)$ means $v_0$ cannot proceed until $v_1$ releases its lock.
   * Under Two-Phase Locking (2PL), $v_1$ cannot release its locks until it completes and commits.
   * But $v_1$ cannot complete because it is waiting for $v_2$, which is waiting for $v_3$, $\ldots$, which is waiting for $v_{k-1}$, which is waiting for $v_0$.
3. Therefore, for every transaction $v_i \in C$, progress depends on $v_{(i+1) \bmod k}$.
4. Since every transaction in $C$ requires another transaction in $C$ to make the first move, no transaction in $C$ can ever transition to `COMMITTED` without external abort.
5. Hence, the transactions in $C$ are permanently deadlocked. $\quad \blacksquare$

**Part 2: $(\Longrightarrow)$ Deadlock State $\implies$ Directed Cycle**

1. Assume a finite set of transactions $S = \lbrace v_0, v_1, \ldots, v_{k-1} \rbrace$ is permanently deadlocked, meaning every transaction $u \in S$ is blocked waiting for some lock held by another transaction in $S$.
2. Because each transaction $u \in S$ is actively waiting on some member of $S$, every vertex has out-degree at least 1 in $G[S]$:
   $$\forall u \in S, \quad \text{outdeg}(u) \ge 1$$
3. Construct a directed walk starting at an arbitrary vertex $u_0 \in S$. Because $\text{outdeg}(u_0) \ge 1$, there exists an outgoing edge to some $u_1 \in S$. Continuing this process yields a sequence of vertices:
   $$W = u_0 \longrightarrow u_1 \longrightarrow u_2 \longrightarrow u_3 \longrightarrow \ldots$$
4. Since $S$ is finite with $|S| = k$, by the **Pigeonhole Principle** (MIT 6.042J Lecture 16), in any sequence of $k + 1$ vertices chosen from a set of size $k$, at least one vertex must appear more than once:
   $$\exists \, i, j \quad \text{such that } 0 \le i < j \le k \quad \text{and} \quad u_i = u_j$$
5. The subsequence $u_i \longrightarrow u_{i+1} \longrightarrow \ldots \longrightarrow u_j$ begins and ends at the identical vertex $u_i$, forming a closed directed cycle. $\quad \blacksquare$

### 2.2 Theorem 2: Time Complexity of Tarjan's SCC Algorithm

<div class="math-theorem">
  <div class="theorem-header">Theorem 2 (Tarjan Linear Bound)</div>
  <p>
    Robert Tarjan's Strongly Connected Components algorithm detects all directed cycles in a Wait-For Graph $G = (V, E)$ in strictly linear time:
    $$\mathcal{O}(|V| + |E|)$$
  </p>
</div>

#### Proof:

1. **Vertex Traversal:** The algorithm performs a Depth-First Search (DFS) traversal. The array `dfn` ensures that every vertex $u \in V$ is visited and pushed onto the recursion stack exactly once:
   $$\sum_{u \in V} \mathcal{O}(1) = \mathcal{O}(|V|)$$
2. **Edge Traversal:** During the DFS visit of vertex $u$, the algorithm iterates through each outgoing directed edge $(u \to v) \in E$ exactly once. For each edge, the `low[u]` update is computed in $\mathcal{O}(1)$ time:
   $$\sum_{u \in V} \text{outdeg}(u) = |E| = \mathcal{O}(|E|)$$
3. **Stack Operations:** Each vertex is pushed onto `stack` once when discovered, and popped once when its SCC root condition (`low[u] == dfn[u]`) is satisfied. Total stack operations across all SCCs are bounded by $2|V|$:
   $$\mathcal{O}(|V|)$$
4. Combining all components:
   $$T(|V|, |E|) = \mathcal{O}(|V|) + \mathcal{O}(|E|) + \mathcal{O}(|V|) = \mathcal{O}(|V| + |E|) \quad \blacksquare$$

### 2.3 Theorem 3: Optimality of Cost-Weighted Victim Selection

<div class="math-theorem">
  <div class="theorem-header">Theorem 3 (Minimal Discarded Work Optimality)</div>
  <p>
    Let $C$ be a detected directed deadlock cycle. To break the cycle, exactly one transaction $v \in C$ must be aborted.
  </p>
  <p>
    Selecting the victim $T^* = \arg\min_{T \in C} \text{Cost}(T)$ provably minimizes the total discarded computational work across the database cluster.
  </p>
</div>

#### Proof:

1. Let $\text{Cost}(T) = \alpha \cdot \text{ElapsedMs}(T) + \beta \cdot \text{RowsModified}(T) + \gamma \cdot \text{Priority}(T)$ denote the computational penalty incurred by rolling back transaction $T$.
2. To eliminate cycle $C$, at least one directed edge $(u \to v) \in C$ must be removed.
3. Aborting any transaction $T_k \in C$ removes all incident edges to and from $T_k$, breaking the cycle $C$.
4. The total work discarded by aborting transaction $T_k$ is exactly $\text{Cost}(T_k)$.
5. Because $\text{Cost}(T) \ge 0$ for all $T$, the global minimum of discarded work across all valid single-transaction cut candidates in cycle $C$ is uniquely achieved by:
   $$T^* = \arg\min_{T \in C} \text{Cost}(T)$$
6. Therefore, no other single-transaction abort strategy can discard less computational work. $\quad \blacksquare$

## 4. Implementation Walkthrough

### 4.1 Tarjan SCC Traversal Implementation

The core cycle detector in [`TarjanDeadlockDetector.java`](file:///home/ahmedashour/Desktop/After-Graduation-Plan/discrete-math-for-backend-engineers/backend-lab/src/main/java/com/backend/discrete/week03_graphs/TarjanDeadlockDetector.java) traverses vertices and extracts directed cycles:

```java
public class TarjanDeadlockDetector implements DeadlockDetector {

    @Override
    public List<DeadlockCycle> detectCycles(WaitForGraph graph) {
        WaitForGraph snapshot = graph.snapshot();
        Set<TransactionId> vertices = snapshot.getVertices();

        Map<TransactionId, Integer> dfn = new HashMap<>();
        Map<TransactionId, Integer> low = new HashMap<>();
        Deque<TransactionId> stack = new ArrayDeque<>();
        Set<TransactionId> onStack = new HashSet<>();
        List<List<TransactionId>> sccs = new ArrayList<>();
        int[] index = new int[]{0};

        for (TransactionId v : vertices) {
            if (!dfn.containsKey(v)) {
                strongConnect(v, snapshot, dfn, low, stack, onStack, sccs, index);
            }
        }

        List<DeadlockCycle> cycles = new ArrayList<>();
        for (List<TransactionId> scc : sccs) {
            if (scc.size() > 1) {
                DeadlockCycle cycle = extractCycle(scc, snapshot);
                if (cycle != null) cycles.add(cycle);
            }
        }
        return cycles;
    }
}
```

### 4.2 Minimum-Cost Victim Selection

In [`MinimumCostVictimSelector.java`](file:///home/ahmedashour/Desktop/After-Graduation-Plan/discrete-math-for-backend-engineers/backend-lab/src/main/java/com/backend/discrete/week03_graphs/MinimumCostVictimSelector.java), the victim is chosen deterministically:

```java
public class MinimumCostVictimSelector implements VictimSelector {

    @Override
    public TransactionId selectVictim(DeadlockCycle cycle, Map<TransactionId, TransactionMetadata> metadataMap) {
        long now = System.currentTimeMillis();

        return cycle.transactions().stream()
                .min(Comparator
                        .<TransactionId>comparingDouble(tx -> {
                            TransactionMetadata meta = metadataMap.get(tx);
                            if (meta == null) return 0.0;
                            return meta.computeRollbackCost(now, ageWeight, rowsWeight, priorityWeight);
                        })
                        .thenComparing(TransactionId::value))
                .orElseThrow();
    }
}
```
