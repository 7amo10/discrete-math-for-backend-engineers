## Why Math for Backend Engineering?

High-scale backend architectures are not built on ad-hoc intuition; they are built on formal invariants, algebraic structures, and graph theorems:

<CardGrid stagger>
  <Card title="State Machine Invariants" icon="seti:lock">
    Proving financial balance conservation ($\sum B_i(t_n) \equiv \sum B_i(t_0)$) across concurrent transfers and partial Saga rollbacks.
  </Card>
  <Card title="Modular Arithmetic & Hashing" icon="seti:graphql">
    Preventing hotspot partitioning via consistent hash rings ($[0, 2^{32}-1]$) and virtual node load balancing in Kafka and Cassandra.
  </Card>
  <Card title="Graph Theory & Cycles" icon="seti:project">
    Eliminating transactional deadlocks in database storage engines via Wait-For Graph (WFG) cycle detection in $O(V + E)$ time.
  </Card>
  <Card title="Posets & Topological Sorting" icon="setting">
    Orchestrating workflow DAG execution engines, identifying concurrent antichains, and resolving Spring Bean circular dependencies.
  </Card>
